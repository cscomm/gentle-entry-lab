# Project rules

- Product data lives in `src/data/products.ts`; a product is cross-listed in another category by adding a `subModels` entry with its slug there, so one detail page serves every category. Why: avoids duplicate pages and keeps admin show/hide toggles consistent.
- A standalone product that is also listed in an advanced-series category's `subModels` must be added to `standaloneSlugs` in `products.ts`. Why: otherwise the generator creates a second, generic copy with the same slug.
- Product-specific detail sections that are large go in `src/components/product/` and are mounted conditionally from `src/pages/ProductDetail.tsx`. Why: that page is already very long.
- New product categories must be added to `ProductCategoryBar`, `SiteHeader` product menu, the homepage category/card lists, the admin `ProductsTab` order, and `scripts/prerender.ts`. Why: each list is maintained separately and search engines read only the prerendered HTML.
- The AI product finder edge function reads `supabase/functions/product-finder/catalog.ts`, generated by `scripts/generate-finder-catalog.ts` (runs in `build`); rerun it and redeploy `product-finder` after product data changes. Why: edge functions cannot import `src/`.
- AI product finder requests are logged server-side by the `product-finder` edge function into `product_finder_logs` (service-role only, no public policies) and read in the admin panel via `admin-crm` actions `finder_logs` / `delete_finder_log`. Why: logging in the browser could be skipped or forged, and the log contains visitor input.
- Long body copy in public pages is rendered with `Prose` (`src/components/Prose.tsx`) instead of `<p>`; it splits text at line breaks and long sentences via `src/lib/paragraphs.ts`. Why: keeps every description readable without hand-editing paragraph breaks in data.
- Member accounts use a separate external auth server (client in `src/lib/members/client.ts`, profile kept in user metadata and copied by `member-api` action `sync_profile` into service-role-only `member_profiles`, which the admin panel reads via `admin-crm` action `member_profiles`); members-only server actions go through the `member-api` / `product-finder` edge functions, which verify the member token via `supabase/functions/_shared/member-auth.ts`. Why: the site's own backend cannot read the external server's sessions, so every gated action must re-check the token server-side.
- Member pages (`/login`, `/signup`, `/account`, `/reset-password`) are intentionally not in `scripts/prerender.ts` and set `noindex`. Why: they carry no searchable content.
- AI product finder usage limits live in `supabase/functions/product-finder/quota.ts` (pure, unit-tested from `src/lib/members/finderQuota.test.ts`) and are enforced in the edge function by counting a member's non-error rows in `product_finder_logs`; visitors who are not signed in are refused server-side. Why: a browser-side counter could be cleared or skipped.
- Social sign-in and sign-up email links return to `/auth/callback` (top-level route outside the `/{lang}` prefix, page `src/pages/AuthCallback.tsx`); the intended language/next page is saved in localStorage beforehand. Why: the member server only accepts return addresses on its exact Redirect URLs list, which can't vary by language or query string.
- Admin product memos (prices, internal notes) live in service-role-only `product_admin_notes`, read/written via `admin-crm` actions `product_notes` / `set_product_note`, never in the publicly readable `product_visibility`. Why: memos may contain prices that must not reach visitors.
- Static SEO HTML for every page/language is built by `scripts/prerender.ts` with per-language content from `scripts/prerenderContent.ts` (product pages render from the MCP catalog; every catalog slug gets a page automatically, admin-hidden products are skipped). Why: non-JS crawlers (Naver, social bots) must see each language's own text, and pages without static HTML fall back to the home page's canonical.
- All absolute site URLs (canonical, hreflang, og:url, sitemap, robots, JSON-LD, IndexNow) use `https://www.silica.co.kr`. Why: the bare domain redirects to www, and redirecting canonicals cause indexing errors.
- Product pages carry no Product/Offer structured data. Why: products have no public price; a placeholder ₩0 offer is misleading in search results.
